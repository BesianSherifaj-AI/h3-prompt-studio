# H3 Prompt Studio Comfy bridge

This folder is a frontend-only Comfy custom extension. It adds an **Open in H3 Prompt Studio** action to native MiniMax H3 prompt nodes and supported downstream conditioning/latent nodes. The menu also contains actions for opening a selected node and controlling the optional GPU guard.

Start the local Studio at `http://127.0.0.1:8766`. Right-click the intended H3 prompt node and choose the Studio action. A closable panel imports its exact prompt, mode, native duration, geometry and connected Load Image files. The Studio Return button updates only that original prompt after validation; it does not queue a generation. If the Comfy prompt changed, review both versions before explicitly replacing it. If the workflow, node, images or dimensions changed, import the current node again.

The embedded panel retains its return connection when ComfyUI Desktop sends ordinary popups to a system browser. Studio must allow embedding by the configured local Comfy origins. Messages use an exact source window, origin and random session. Prompt/image contents are never placed in the URL.

**Send to ComfyUI** in Studio can also open a complete prepared workflow with its uploaded image inputs and selected generation settings. It opens a new native workflow tab and preserves the existing workflow draft. From the embedded editor this happens in the same ComfyUI window; from standalone Studio it opens ComfyUI with a short-lived random transfer ticket. The ticket contains no prompt or image data. The receiver checks its destination and expiry, prevents duplicate application in the same browser session, and offers **H3 Prompt Studio → Retry Studio transfer** after a connection failure. It never presses Run or submits a queue. The explicitly sent workflow automatically enables the existing scoped GPU guard so the user's subsequent Run releases the prompt model first.

Before opening the workflow, the receiver reads each prepared image from ComfyUI and verifies its exact byte count and SHA-256 against the transfer manifest. It then adds those verified files to the imported nodes' own image selectors, as ComfyUI's native upload button does. This handles transfer subfolders that the core Load Image catalog does not list and prevents false “Missing Inputs” messages. A missing or changed file stops the transfer before opening a graph. Other workflows' image choices are unchanged.

Saved Studio workflow files retain their verification manifest. Reopening one repeats the image checks without requiring a live transfer ticket or Prompt Studio. If an image is missing or changed, a clear message is shown and the graph remains editable with ComfyUI's ordinary missing-media indicators. Unknown workflow metadata is preserved.

Studio-generated **MMH3 Save** nodes provide **Continue this result in Prompt Studio** after execution. This opens a review for the original project and exact saved state, with an optional next seed read from its authoritative Create control. It does not generate, load a model, or alter the graph. After reopening a workflow, the button can recover its saved output from the frontend cache or explicitly read the latest successful history record matching that exact project, transfer, Save node and filename prefix. It never chooses another workflow's latest result. The upstream F04-only continuation button is hidden on these Studio Save nodes because its required Review/Prepare graph is absent.

For Studio native H3 exports with linked prompt controls, import and prompt-only return follow only the declared, typed **Create → Inspect → H3** path and edit Create's actual prompt. Arbitrary linked prompts remain unsupported. Saved-state continuation graphs use their Save-node continuation action instead of native prompt-only import.

Imports from a selected H3 node now include the connected sampling branch's readable settings, including each LoRA and its strengths. Connected widget values are marked as connected instead of presenting their stale local value. Unrelated sampling branches that merely share a model loader are excluded.

Only PNG, JPEG and WebP loaded through native Load Image nodes are imported, optionally through transparent native reroutes. Limits are 8 MiB per image and 32 MiB total, with at most nine Ref2VA images. Image processing graphs are not executed. The bridge refuses unsupported dynamic images, linked prompt/dimension widgets, and reference video/audio rather than silently changing their meaning. Internal H3 resize operations are not evaluated. Native duration is aligned frames / 24; 124 frames is about 5.167 seconds.

**Guard Comfy runs** is optional and off until explicitly enabled. Pairing through Studio provides a scoped token that permits only preparing H3 resources. When enabled, a normal Run waits up to 60 seconds for Studio to confirm the AI model is released before the original queue API runs. Failures block submission. The guard stays active after the editor panel closes, so keep Studio running or use **H3 Prompt Studio → Disable GPU guard**. It protects the standard queue API in this frontend, not direct HTTP clients, other Comfy instances, or code that bypasses that API. There is no automatic queue submission and no automatic global guard installation.

For installation, copy this complete folder to your chosen ComfyUI installation's `custom_nodes/H3PromptStudioBridge` directory, then restart that installation and reload its frontend. This source folder does not install or restart anything by itself. Supported browser origins are the local ports 8188, 8000, and 8010.

CPU checks: `node --test comfy_extension/tests/*.test.mjs` from the repository root. See [ComfyUI setup](../COMFY_BRIDGE_SETUP.md) for the complete runtime and model requirements.
